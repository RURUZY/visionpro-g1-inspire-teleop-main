# G1 干滚筒刷墙：MuJoCo 先导实验

本实验复用 Vision Pro → SONIC → G1 + Inspire 手链路，先验证抓持、可达性和
墙面接触。场景包含独立自由工具、被动滚筒转轴、带杯托的立柱及竖直墙板。滚筒没有
绑定到机器人手上，需要通过手指接触抓住；墙面目标色块只是无碰撞标记。

这是干滚筒的刚体接触仿真，不模拟蘸漆、颜料转移、漆膜厚度或涂层质量。
新入口不包含自动抓取、自动刷动或恒力控制。真实接触效果须由遥操作试验验证。
默认侧后方视角能同时看到胶柄和墙面目标区，并显示 MuJoCo 接触点与力箭头。

## 启动

三个终端都进入项目目录，沿用 `.env` 中已经可运行的 SONIC/MuJoCo 配置。
首次启动或切换场景时，先退出原有抓取场景、deploy 和桥接进程，避免复用同一通信端口。
同一场景里重复练习时保留三个进程和 Tracking Streamer；刷子掉落用下述 R 键复位即可。

```bash
cd /home/epcap/projects/visionpro-g1-inspire-teleop-main

# 终端 1：生成刷墙场景，启动仿真及接触记录
bash run_sonic_sim_loop_paint.sh

# 终端 2：明确选择仿真
bash run_sonic_deploy.sh sim

# 终端 3：原 IP、自动按键、头显画面；T 后直接开启头显行走
bash bin/sonic-teleop-paint.sh --auto

# 自动校准结束后，可在终端 3 接入查看桥接状态
tmux attach -t tele
```

终端 1 应显示 `Camera publish: ON`；桥接日志出现
`[mujoco_fpv] First camera frame buffered` 表示电脑已读到首帧；
`[mujoco_fpv] Headset video connection established` 表示头显视频连接已建立，
最终显示仍以佩戴者看到的画面为准。连接通知会等视频服务器和追踪就绪后发送，
失败或断流重连后自动重试。如果 Tracking Streamer 有单独的视频/沉浸显示开关，还需将其打开。
`--no-mujoco-fpv` 会关闭头显回传，只在明确需要仅看电脑窗口时使用。

需要验证先前的仿真拇指全行程设置时，终端 3 额外加 `--sim-thumb-full-range`。
保留现有个人校准；改变输出范围后先空手检查，再开始新一组试验。
上述命令只启用仿真手输出。

入口默认沿用 IP `192.168.2.5`；要指定地址可用
`bash bin/sonic-teleop-paint.sh 192.168.2.5 --auto`。
`--auto` 调用原有 `solo_teleop.sh` 自动按 `F → ] → S → T`，以终端实际提示为准；操作者仍需保持
校准姿势，并在落地环节按 Enter 确认。需要手动按键时，改用
`bash bin/sonic-teleop-paint.sh 192.168.2.5`，该入口默认开启头显回传。
双手都接收手腕与手指目标，沿用已录制抓盒子工作流的 `official-calib` 映射、
缩放、腕部方向和平滑参数。启动校准时两只手都要保持可追踪。SONIC 仍负责全身平衡。
保持每组的弹力带设置一致，并在记录中保留其状态；已落地时不要盲目按 `9`。

### 调整站位

保留头显前后移动控制，关闭键盘移动。自动校准结束并进入 T 后，头显行走
直接生效，不再默认锁定，也不需要按 B 解锁；空格不再充当行走锁定开关。
手臂、手指继续遥操作，SONIC 仍会做全身平衡调整。

开启行走后的指令上限为 0.15 m/s，关闭头部高度控制下蹲。
这里用的是头显位置变化的速度：身体带着头显向前移动时发出
前进指令，向后移动时后退；停止移动后指令逐渐回零。不是点头控制，也不是
把头停在前方就持续前进。原有头部转向控制仍保留。

自动按键结束后，可执行 `tmux attach -t tele` 查看桥接状态。
W / S / A / D / , / . 不控制移动；校准阶段的 S 仍用于校准。

先空手慢慢伸手、收手，观察身体是否仍明显晃动。确认手臂跟随后，
再用头显移动调整距离，停止移动并观察站稳，最后抓滚筒。
更新场景后需要重启终端 1；更新移动参数后需要重启终端 3，旧进程不会自动加载。

首次使用依赖已有 `assets/mujoco/g1_runtime/g1_29dof_with_inspire_hand.xml`。
如缺失，按原工程流程用仿真 Python 执行 `tools/setup_inspire_sim.py`；不要把
场景生成器当作模型或依赖安装器。

## 场景与抓握

机器人面向 +X，右侧为 -Y。场景里没有桌子，机器人和墙之间没有遮挡物。

- **刷子与杯托**：滚筒刷竖直插在右前方立柱顶部的杯托里，刷柄朝下、滚筒朝上，
  滚筒轴沿 Y（拿起后已与墙面平行），弯曲支架朝外侧（-Y）。立柱中心
  (0.38, -0.30) m，杯托底面高 0.81 m、深 6 cm，柄与杯壁单侧间隙 2 mm，
  静置时刷柄略有倾斜。抓握标记（柄上露出部分的中点）约在 (0.38, -0.30, 0.92) m。
  杯托只起支撑作用，没有把工具固定住。
- **抓法**：右手从侧面握住竖直刷柄，拇指朝上，直接向上提出杯托。
- **墙板**：自立式墙板前表面在 x=0.60 m，宽 1.0 m、高 0.6 m，中心高 1.22 m，
  下沿 0.92 m。目标区中心约 (0.5985, -0.15, 1.22) m，宽 24 cm、高 30 cm，在右手前方。
- **刷墙姿态**：握住刷柄，让刷柄下端朝机器人倾斜约 15–35°，滚筒贴墙上下滚动。

默认尺寸是按以下检查选的（`tests/test_paint_scene.py` 会自动复查）：

1. 以录制的站立姿态做右臂 IK：不走路即可握到刷柄；滚筒在目标中心及上下 10 cm
   都能贴墙，关节离限位留有余量。
2. 用录制的抓方块启动/落地姿态（按 9 落地时机器人会前冲约 12 cm、双手前甩）检查：
   全程与墙、立柱、杯托和刷子至少保持约 2.5 cm 间隙。
3. 头部仿真相机初始画面里同时能看到抓握标记和整个目标区。

以上是静态几何检查，不代表闭环落地、抓取或刷墙一定成功，仍需遥操作验证。

刷墙场景单独生成 `g1_inspire_paint_view.xml`，只调整头部仿真相机的朝向和视角：
向下约 21°、垂直视场 80°，让墙面目标和杯托里的刷柄同时入画。
原来的共享 G1 模型、抓方块相机及机器人动力学参数不变；这不是实机相机标定。

生成器 `python3 tools/generate_paint_scene.py --help` 列出可调整参数。
例如先生成另一墙距的场景，再用显式路径启动，避免被默认生成覆盖：

```bash
python3 tools/generate_paint_scene.py --wall-x 0.65 --output-dir assets/mujoco/generated/paint_far
SONIC_PAINT_SCENE="$PWD/assets/mujoco/generated/paint_far/scene_43dof_inspire_hand_paint.xml" \
  bash run_sonic_sim_loop_paint.sh
```

每次改墙距、工具位置、摩擦、手指配置或站姿，都另开一组试验，保留对应场景。
对自定义场景执行准备检查时，也将相同文件路径传给 `prepare_paint_test.py --scene`。

## 一轮怎么做

先练习，再在相同设置下做 5 次正式试验，保留失败记录。

1. **抓持**：右手握住竖直刷柄，向上提出杯托约 10 cm，保持 3 秒。确认工具随手移动，
   没有靠杯托继续支撑。失败时先解决抓握，不继续顶墙。
2. **空中轨迹**：工具悬空做一段约 10 cm 的竖直运动，观察腕部姿态和柄部滑动。
3. **接触**：靠近墙面，将滚筒移到目标区内，缓慢建立接触，短暂停留。
4. **刷动**：做约 10 cm 的上、下、上三条单程轨迹，每条约 3–5 秒。这是先导
   动作目标，不是验证过的控制参数；遇到明显挤压、工具滑落或失稳即结束该次。
5. **退出**：离开墙面，将刷柄插回杯托并松手，记录结果与失败阶段。

一次任务完成应包含抓起、悬空保持、三条刷动及放回。另行记录接触中断和
滑移情况，不把“手走过了轨迹”当作“滚筒持续接触墙面”。
不要把鼠标外力、工具复位或焊接约束当作正式试验中的成功抓取。

## 刷子掉落后继续练习

先停止移动，张开手并把双手移离杯托。点击 MuJoCo 窗口，按 **R**：
刷子回到杯托里的初始位置，机器人站位、仿真时间、校准和头显连接继续保留。
如果返回位置被手或其他物体占用，终端 1 提示 `Return position occupied`，移开后再按 R。
R 只在仿真窗口生效，原来的 7 / 8 / 9 弹力带按键继续保留。

每次成功复位在 `events.jsonl` 记录 `manual_tool_reset`，随后开始新的 episode。
复位是练习辅助，上一段抓取失败仍需保留，不能计作自动捡回成功。

## 重开终端 3 时的连接

保持 Vision Pro 上的 Tracking Streamer 打开并处于追踪状态，再运行原来的终端 3 命令。
电脑端现在会先让旧桥接正常退出、关闭追踪连接，然后建立新连接；等不到首帧或断流时自动重试。
连接恢复时会显示 `[avp_connection] Fresh tracking received.`，之后继续原来的自动校准。
首帧等待、断流重试和关闭连接已做离线测试，头显端能否每次正常恢复仍需现场验证。
如果仍无法识别，保留 `/tmp/solo_bridge.log`，根据新的连接日志继续定位。

这套顺序比完整开门更容易控制变量：带门锁的开门还包括把手抓握、解锁，
随后沿门铰链圆弧协调手臂与身体；可以在本接触实验之后另设任务。

## 记录与验收范围

终端 1 打印 `recordings/paint_diagnostics_*` 路径。记录器以仿真时间采样，保存：

- `model.mjb`、`metadata.json`：实际编译模型、采样信息和参数边界；
- `samples.csv`：工具、滚筒、手腕及骨盆位姿，采样时的系统时间，工具相对右腕的变化，滚筒转角，滚筒—墙、
  工具—支架（立柱与杯托，列名仍为 tool_table）、手—工具的接触数量及力，episode、弹力带状态；
- `recording_status.json`：正常关闭后的写入状态。
- `events.jsonl`：有人工工具复位时生成，记录复位时间、前后位姿及新 episode。

接触力来自 MuJoCo 求解器，既不是实机传感器读数，也不说明控制器实现了恒力。
骨盆位姿从 schema 2 开始记录，用于区分身体晃动和手腕运动；旧记录没有这些列。
相对手腕的运动可能来自抓握调整或滑移，需要结合视频与手指接触判断。
50 Hz 采样可能漏掉更短的接触事件。记录器不会自动判定每条刷动的起止或成功率。

生成场景后，用能导入 MuJoCo 的 Python 创建空白试验表：

```bash
~/.config/visionpro-g1-inspire-teleop/venv_sonic_sim/bin/python tools/prepare_paint_test.py
```

如果使用自定义仿真环境，将上面的 Python 换成该环境。输出 `preflight.json` 和
五行 `not_run` 的 `trials.csv`。该检查只确认模型结构、碰撞配置和 SONIC 索引，
不执行抓取或刷墙，也不会把未运行试验记为成功。
每行记录日志目录、episode、刷动开始/结束的仿真时间、完成条数、掉落/失稳及
人工干预。接触力、相对姿态和轨迹数据用于分析失败原因；涂层效果需另做实验。
